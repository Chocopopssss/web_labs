# Лабораторная работа №5: Тестирование API с помощью pytest

## Описание проекта

Данный проект представляет собой расширение веб-приложения на базе FastAPI из Лабораторной работы №4. В этой части реализовано комплексное автоматизированное тестирование REST API и бизнес-логики с использованием фреймворка `pytest`, клиента `TestClient` и библиотеки `unittest.mock`.

Проект сохраняет принципы чистой архитектуры (разделение на слои роутеров, сервисов, репозиториев и Pydantic-схем) и запускает все тесты в изолированном Docker-контейнере.

## Реализованные тесты

В рамках лабораторной работы покрыты все основные уровни и сценарии тестирования:

### 1. Интеграционные тесты API (`tests/test_api.py`)
* **`test_root`** — проверка доступности корневого эндпоинта `GET /` (ожидается статус `200 OK`).
* **`test_create_user`** — позитивный сценарий создания нового пользователя через `POST /users/` с валидными данными (`name`, `email`, `age`) и проверка статуса `201 Created`.
* **`test_create_user_duplicate_email`** — проверка обработки конфликта при попытке регистрации пользователя с уже существующим email (ожидается статус `409 Conflict`).
* **`test_get_user_not_found`** — проверка ошибочного сценария при запросе несуществующего пользователя `GET /users/9999` (ожидается статус `404 Not Found`).

### 2. Граничные и ошибочные сценарии (`tests/test_api_boundaries.py`)
* **`test_create_user_invalid_age_negative`** — проверка валидации при передаче отрицательного возраста (`age = -5`, ожидается статус `422 Unprocessable Entity`).
* **`test_create_user_invalid_age_too_old`** — проверка верхней границы возраста (`age = 150`, ожидается статус `422 Unprocessable Entity`).
* **`test_create_user_invalid_name_short`** — проверка минимальной длины имени (`min_length=2`, ожидается статус `422 Unprocessable Entity`).

### 3. Unit-тесты бизнес-логики с моками (`tests/test_services.py`)
* **`test_service_create_user_success`** — изолированное тестирование метода `create_user` в `UserService` с подменой слоя репозитория через `MagicMock`.
* **`test_service_create_user_duplicate_email`** — проверка выброса исключения `HTTPException (409)` на уровне сервиса при имитации существующего пользователя в репозитории.

## Запуск тестов

Перейдите в директорию `lab5/` и выполните команду:

```bash
docker compose up --build
```
Контейнер автоматически соберёт образ, установит зависимости и запустит прогон всех тестов (`python -m pytest -v`).
